从设计到部署，这里记录我搭建个人网站的过程，以及为什么它长得像一张纸。

## 为什么又写了一个网站

我做过几个后台系统，界面都很"能用"，但也都很吵：满屏的卡片、渐变、徽章、动效。后来我想给自己做一个安静的地方，用来放项目、笔记和一些零碎的记录。于是就有了这个站点。

它的第一原则不是"好看"，而是**不打扰**：

- 不用高饱和色，主色是米白与灰棕
- 不用大渐变，不用玻璃拟态
- 动画只做位移与透明度，不做弹跳
- 留白优先于信息密度

## 结构

整个站点只有五个入口：

| 路径 | 作用 |
| --- | --- |
| `/` | 首页：自我介绍 + 站点统计 + 最近项目 |
| `/projects` | 项目档案，纵向排列，细线分割 |
| `/notes` | 记录技术、生活与灵感 |
| `/tools` | 纯前端小工具箱 |
| `/about` | 更个人化的介绍 |

技术上是 Vue 3 + TypeScript + Vite。没有用 UI 框架，样式是手写 SCSS，所有颜色都收敛成 CSS 变量，这样主题切换只需要替换变量：

```css
:root[data-theme='light'] {
  --bg: #f3eedf;
  --surface: #faf9f5;
  --text-primary: #353535;
  --accent: #8f887a;
}

:root[data-theme='dark'] {
  --bg: #20201f;
  --surface: #292928;
  --text-primary: #ebe7dd;
  --accent: #aba292;
}
```

## 关于数据来源

起初项目区是走 GitHub API 的，想着仓库一更新，站点上的项目信息就自动跟着变。实际做下来这条路不太顺：公司的网络经常拦截 API 请求，未认证的配额又只有每小时 60 次，构建期的快照也常常抓不到东西。为了兜住这些失败情况，数据层长出缓存、降级、重试、冷却一整套逻辑，比页面本身还复杂。

后来我把整套 GitHub 抓取都删掉了。现在所有内容都来自仓库里的静态数据文件：

```ts
// data/projects.ts —— 项目档案，全站唯一数据源
// data/notes.ts    —— 笔记
// data/tools.ts    —— 工具清单
```

站点因此没有任何运行时请求，也没有加载态、失败态和重试按钮——首页的统计数字（项目数 / 笔记数 / 工具数）直接由这几份数据现算。代价是加项目要手动改文件，但对这个量级的站点来说，这比维护一套抓取降级链路划算得多。

## 关于那些藏在角落里的东西

Logo 是一对简化的耳朵轮廓，背景是很淡的点阵，404 页面里坐着一只背对屏幕的兽人。

> 它们是这个站点的一部分，但不是这个站点的主题。

我希望别人先看到一个干净的开发者网站，然后在某一页突然发现一点个人的东西。这样就够了。

## 部署

`npm run build` 之后是一个纯静态目录，扔到任意静态托管上都能跑。没有服务端，也没有数据库。
